-------------------------------------------------------------------------UTILITY PURPOSE EXPLANATION-------------------------------------------------------------------------
This concept is called "ChromiumBrowseProtect". ChromiumBrowseProtect is a theoretical protection utility to prevent malware (such as info stealers) from stealing from Chromium based browsers. ChromiumBrowseProtect consistently monitors for suspicious commands, potential injection attempts, and suspicious interaction with browser files (such as copying credential files). It is dedicated to defending chromium-based-browsers from post-exploitation stealer attempts. It is not an antivirus.

-------------------------------------------------------------------------UTILITY BASIC REPONSE LOGIC EXPLANATION-------------------------------------------------------------------------

-----------------DEFAULT ACTION LOGIC-----------------
If a suspected file is also found to be unsigned then it is treated with higher urgency (intsantly terminating the process).

Suspected files processes will be suspended and the user will be given a "Yes" or "No" question. The action will be based off if the user says "Yes" or "No".

If suspected file is already white-listed no action will be taken.
------------------------------------------------------

-----------------USER QUESTION LOGIC-----------------

If the user to a question says "No", then ChromiumBrowseProtect will terminate the process and send the file to a reputable sandbox providers (such as hybrid-analysis.com). ChromiumBrowseProtect will then delete the suspicious file and recommend a deep-antivirus scan with the user's current Antivirus solution.

If the user to a question says "Yes" then ChromiumBrowseProtect will simply allow the process to continue and ask if the user wants to white-list the file
------------------------------------------------------

-----------------FAILURE-HANDLING LOGIC-----------------
If an attempted process termination fails then ChromiumBrowseProtect will attempt to restart itself. If it still fails then ChromiumBrowseProtect will alert to the user that the computer may be compromised and to seek help from their antivirus support team for verification.

If ChromiumBrowseProtect fails to make or recreate a Windows registry entry, than ChromiumBrowseProtect will request higher privledges (Administrator). If it continues to fail than ChromiumBrowseProtect will recommend reinstalling ChromiumBrowseProtect.

-------------------------------------------------------------------------UTILITY DETECTION LOGIC EXPLANATION-------------------------------------------------------------------------
Such as a command involving "--remote-debugging-port=9222" directed at a Chromium based browser (such as Chrome). If detected, ChromiumBrowseProtect will suspend the process, and notify the user of this process with a "Yes" or "No" question and explanation of what it is attempting. "Yes" means the process is trusted by the user. "No" means the process is not trusted by the user. If the user answers "Yes", then ChromiumBrowseProtect will allow the process to continue. If the user says "No", then ChromiumBrowseProtect will terminate the process and send the file to a reputable sandbox providers (such as hybrid-analysis.com). ChromiumBrowseProtect will then delete the suspicious file and recommend a deep-antivirus scan with the user's current Antivirus solution. If termination fails then ChromiumBrowseProtect will attempt to restart itself. If it still fails then ChromiumBrowseProtect will alert to the user that the computer may be compromised and to seek help from their antivirus support team for verification.

If process injection, memory injection, or any form of injection aimed at a Chromium based browser application then ChromiumBrowseProtect will immediately suspend the file. If this process is injecting into an inactive debugger browser process (often called a "zombie process") then that process is also to be immediately terminated. If process termination fails than ChromiumBrowseProtect alert the user and attempt to restart itself. If termination still fails then ChromiumBrowseProtect will alert to the user that the computer may be compromised and to seek help from their antivirus support team for verification. ChromiumBrowseProtect will notify the user of the attempted injection. ChromiumBrowseProtect will present a "Yes" or "No" question but it will be strongly recommended to say "No". If the user answers "No", then ChromiumBrowseProtect will upload the file to a reputable sandbox provider. If the user answers "Yes", then ChromiumBrowseProtect will do nothing more with the file unless told otherwise. It will then ask the user if they want to white-list the suspected file. If they answer "Yes", then  ChromiumBrowseProtect will add the browser path to a local storage file for exceptions to avoid further flagging of the file. However, if the user answers "No", nothing more will be done with the suspected file. 

If a suspicious command such as "[chromium based browser].exe --no-sandbox --disable-extensions" is detected, then ChromiumBrowseProtect will suspend the process and notify the user of this process with a "Yes" or "No" question and explanation of what it is attempting. If the user answers "Yes", then ChromiumBrowseProtect will allow the process to continue. If the user says "No", then ChromiumBrowseProtect will terminate the process and send the file to a reputable sandbox providers (such as hybrid-analysis.com). ChromiumBrowseProtect will then delete the suspicious file and recommend a deep-antivirus scan with the user's current Antivirus solution. If termination still fails then ChromiumBrowseProtect will attempt to restart itself. If it still fails then ChromiumBrowseProtect will alert to the user that the computer may be compromised and to seek help from their antivirus support team for verification.

Consistently monitor "Browser/User Data". If files are being copied from the User Data directory than ChromiumBrowseProtect will check the process doing it. If the process does not belong to the browser that owns that specific User Data folder, then ChromiumBrowseProtect will suspend the process and notify the user of this process with a "Yes" or "No" question and explanation of what it is attempting. If the user answers "Yes", then ChromiumBrowseProtect will allow the process to continue. If the user says "No", then ChromiumBrowseProtect will terminate the process and send the file to a reputable sandbox providers (such as hybrid-analysis.com). ChromiumBrowseProtect will then delete the suspicious file and recommend a deep-antivirus scan with the user's current Antivirus solution. However, if the binary is also unsigned (Unknown Provider), then ChromiumBrowseProtect will terminate the process and alert the user to the highly suspicious application. The user will be given a "Yes" or "No" question on if to remove the file. If they answer "Yes", then ChromiumBrowseProtect will remove the file and send the file to a reputable sandbox providers (such as hybrid-analysis.com). If they answer "No", ChromiumBrowseProtect will do no more with the application from that point. It will then ask the user if they want to white-list the suspected file. If they answer "Yes", then  ChromiumBrowseProtect will add the browser path to a local storage file for exceptions to avoid further flagging of the file. However, they will still be recommend a deep anti-virus scan to be safe.

-------------------------------------------------------------------------UTILITY SELF-PROTECTION LOGIC EXPLANATION-------------------------------------------------------------------------
--------------CBPwatch Module--------------
The self-protection logic includes one module ("CBPwatch"). CBPwatch (ChromiumBrowseProtect Watch) will do an integrity check on ChromiumBrowseProtect every 15 seconds. This simple check will simply check for the existence of ChromiumBrowseProtect managed files and directories.  However, it will constantly be monitoring for high-priority potential interruption attempts. The following high-priority potential interruption are: Created firewall rules that block ChromiumBrowseProtect, Injection attempts into any ChromiumBrowseProtect managed files, manipulating the exclusions directory, attempts to write to any ChromiumBrowseProtect managed files, or attempts to remove persistence (set SERVICE designed to start on boot).

If a firewall rule is detected attempting to block ChromiumBrowseProtect, then CBPwatch will remove the rule, and inform the user of potential disruption attempts and the reason (or in this case a suspicious firewall rule). 

If it detects attempted injection into any ChromiumBrowseProtect managed files, then it will terminate the affected ChromiumBrowseProtect file process. CBPwatch will then inform the user of attempted disruption (or in this case an injection attempt) and highly recommend a full system scan. 

If set service is not found, then recreate it. Then wait 60 seconds, and check it again. If the service is not found again then CBPwatch will inform the user of potential disruption attempts and the reason (which here is repeated deletion of persistence registry keys) and it will highly recommend a full system scan. However, if the set service is found after 60 seconds of recreation, then assume false alarm. If any missing files are missing, then redownload the missing file, wait 60 seconds, and then check if it is gone again. If it is found missing again then CBPwatch will then inform the user of attempted disruption and highly recommend a full system scan. 

If a separate process (not ChromiumBrowseProtect) writes to the exclusions directory, then ChromiumBrowseProtect will pause the process. Then ChromiumBrowseProtect will notify the user of this process with a "Yes" or "No" question and explanation of what it is attempting. If the user answers "Yes", then ChromiumBrowseProtect will allow the process to continue. If the user says "No", then ChromiumBrowseProtect will terminate the process and send the file to a reputable sandbox providers (such as hybrid-analysis.com). ChromiumBrowseProtect will then delete the suspicious file and recommend a deep-antivirus scan with the user's current Antivirus solution. If termination still fails then ChromiumBrowseProtect will attempt to restart itself. If it still fails then ChromiumBrowseProtect will alert to the user that the computer may be compromised and to seek help from their antivirus support team for verification.

--------------ChromiumBrowseProtect Watchdog logic--------------
ChromiumBrowseProtect will also have similar watchdog logic incase of issues with the CBPwatch Module. ChromiumBrowseProtect will do an integrity check on CBPwatch every 15 seconds. This simple check will simply check for the existence of CBPwatch managed files and directories.  However, it will constantly be monitoring for high-priority potential interruption attempts. The following high-priority potential interruption are: Created firewall rules that block CBPwatch, Injection attempts into any CBPwatch managed files, manipulating the exclusions directory, attempts to write to CBPwatch.

If a firewall rule is detected attempting to block CBPwatch, then ChromiumBrowseProtect will remove the rule, and inform the user of potential disruption attempts and the reason (or in this case a suspicious firewall rule). If it detects attempted injection into CBPwatch, then it will terminate the affected CBPwatch file process. ChromiumBrowseProtect will then inform the user of attempted disruption and highly recommend a full system scan. If set service is not found, then recreate it. Then wait 60 seconds, and check it again. If the set service is not found again then ChromiumBrowseProtect will inform the user of potential disruption attempts and the reason (which here is repeated deletion of the set service) and it will highly recommend a full system scan. However, if the set service is found after 60 seconds of recreation, then assume false alarm. If any missing files are missing, then redownload the missing file, wait 60 seconds, and then check if it is gone again. If it is found missing again then ChromiumBrowseProtect will inform the user of attempted disruption, give the reason (which here is repeated file deletion), and highly recommend a full system scan.

-------------------------------------------------------------------------UTILITY SETUP LOGIC EXPLANATION-------------------------------------------------------------------------
ChromiumBrowseProtect will be installed with an installer named "CBPinstall". ChromiumBrowseProtect (main file) and CBPwatch will be embedded inside CBPinstall as an RCDATA Resource. 

CBPinstall will create a home directory inside "C:\Program Files". CBPinstall will then extract and write ChromiumBrowseProtect and CBPwatch to the disk then place it inside "C:\Program Files\ChromiumBrowseProtect". If CBPinstall fails in this phase than it will inform the user and recommend elevating permissions (assuming it did not already have elevated permissions). If that also fails the user will be instructed to contact the owner/developer. CBP install will then create a subdirectory for exclusions (excluded files will be inputted through making a .txt file with the file name and the path inside the file). Once the home directory has been established, CBPinstall will setup a Windows SERVICE for CBPinstall (you can find service details in the 'Design Spec.txt' file). Once this is successful CBPinstall will start ChromiumBrowseProtect and inform the user that setup is complete.

-------------------------------------------------------------------------UTILITY CONFIG MODULE EXPLANATION-------------------------------------------------------------------------
CBPconfig handles the command line for ChromiumBrowseProtect. CPBconfig will simply consist of 5 commands and some printed comments. However this will be the main way the user configures ChromiumBrowseProtect. On its first startup, CBPconfig will create a json file of all configurations in the home directory titled "CBP_Configs". Each variable will equal "F" or "T". "T" means true, "F" means false. CBPconfig will then suggest you put in a tamper protection password (this means a password is required before you can make any commands every time). If the user agrees, then CBPconfig will create a ".cbp" file titled "tampprotectPass" inside the home directory. It will then prompt the user to input a 6-digit-password. Once the password is inputted, it will be saved to "tampprotectPass.cbp". CBP will then encrypt it with the AES-265 encryption algorithm. The decryption password will be set as the one the user inputted. 

--------------------------COMMANDS--------------------------
"GET current_configs" = Get the current configurations of ChromiumBrowseProtect
"GET current_white-listed" = Get current whitelisted files

"DISABLE realtime_monitoring" = If not already disabled then deactivate the Windows SERVICE and only run if specified and set realtime_monitoring variable in the config file to "F". If already disabled then CPBconfig will print "INVALID: REQUEST ALREADY FUFILLED"
"ENABLE realtime_monitoring" = If already enabled then do no further action CPBconfig will print "INVALID: REQUEST ALREADY FUFILLED". If not then CBPconfig will enable the Windows SERVICE and set realtime_monitoring variable in the config file to "T"

"VIEW white-listed" = Print all the white-listed files

"DISABLE tamper_protection" = If not already, set the "tampprotectPass" variable in the config file to "F" and restart. If already enabled then do no further action CPBconfig will print "INVALID: REQUEST ALREADY FUFILLED".
"ENABLE tamper_protection" = If not already, set the "tampprotectPass" variable in the config file to "T" and restart. If already enabled then do no further action CPBconfig will print "INVALID: REQUEST ALREADY FUFILLED".

"WHITE-LIST [path]" = If not already than add the specified path to the exclusions directory. If already enabled then do no further action CPBconfig will print "INVALID: REQUEST ALREADY FUFILLED".
